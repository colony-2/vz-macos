# Pulse, Tart and Orchard support for the VM API

The proposed Go API covers the VM work Pulse delegates to pulse-tart. All 17 Backend methods have a current conceptual dependency or an identified diagnostic use, but several signatures and guarantees are new. Neither existing adapter implements this Go interface. In particular, typed bootstrap events, separate endpoint observation, capability reporting and richer command results require adapter work.

Here, **Pulse usage** means the production consumer in pulse-tart, not a direct call from Pulse's scheduler. Pulse owns placement and leases. The local Tart adapter and remote Orchard adapter both live in pulse-tart; Orchard is not a separate Pulse provider in this audit. This distinction matters when deciding whether a feature belongs in the shared contract or in provider policy.

The evidence is the original audit and the pulse-tart owner's subsequent coverage review, both for pulse-tart revision `ac235e01e7ca4b3bb65be8d39204d92985af4680`. Source references below are paths and line numbers **in that revision of pulse-tart**, not this repository. The original audit, numbered source excerpts and owner review are retained with the review artifacts. This is a source comparison, not a live test of either backend or proof of Orchard controller internals. The [operation guide](vmapi-operations.md) explains proposed inputs, outcomes and failure handling; the [existing vz-macos analysis](vmapi-analysis.md) identifies later native work.

## Capabilities and behavior without a dedicated method

`ProbeLocalSources` is a capability, not an eighteenth Backend method. Production core uses the current optional boolean hook at `provider/images.go:51–55`. Orchard returns true (`orchard/client.go:187–189`): controller listing cannot enumerate worker-local sources, so core tries disposable clone probes. Tart lacks the hook and defaults false. The new capability preserves that decision; it never licenses List/Get to perform a probe.

The proposed capabilities for OS/clone modes, Docker operations, adoption/retention, recovery/restart delivery and endpoint cleanup/diagnostics replace current structural interface tests. Those tests demonstrate which paths exist, not that every platform guarantee is qualified. In particular, an Orchard Recover hook is absent and controller restart safety was not audited; advertise equivalent RestartDelivery only after separate evidence.

## What is additional rather than an existing Pulse call

There are no separate production pulse-tart calls to the new `GetEndpoint`, richer Info reporting, bounded cursor APIs, immutable endpoint UIDs or generic Exec argv/env/cwd/exit-status interface. Their purpose is to expose the existing conceptual work safely through a common dependency, with broader explicit values where already approved. EndpointDiagnostics has a test-only consumer, not a production consumer. Orchard has no adoption, retention, Recover, RemoveEndpoint or diagnostics hooks; their absence selects the specific fallback above, not fabricated support.

No generic Start, GetOperation, FindOperation, SubmitCommand, ReadOutput or standalone ListSources API remains in the proposed interface. Create includes run/resume and bootstrap; direct Exec returns sensitive bounded output; Get/List plus source capabilities support discovery. The audit did not require a generic operation service. Pulse scheduling/leases, c2j execution renewal and secret retrieval, core recipe/readiness policy, GUI/OCR, image conversion and generalized storage remain outside this API.

Reviewing a mapping as “supported today” must not erase the delta column: native UID validation races, suspended cloning, delivery durability/secrecy and endpoint restoration still require qualification in each future adapter. The [operation guide](vmapi-operations.md) makes those boundaries concrete.

The current API selects a configured Backend before calls. The consumer journals its immutable configuration binding; BackendInfo.ID and bare resource references do not prove routing continuity. This contract does not establish private Orchard worker affinity.
